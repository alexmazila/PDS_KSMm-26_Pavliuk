1. Опис сенсорної архітектури

Сенсорна архітектура розробленої системи призначена для імітації вимірювань фізичного датчика (наприклад, ультразвукового або інфрачервоного датчика відстані), обробки первинних даних та їх подальшої передачі виконавчим або навігаційним нодам робота через систему обміну повідомленнями ROS2.

    Джерело даних (Sensor Simulation): Нода sensor_node генерує випадкові значення у заданому діапазоні (від 0.1 до 2.0 умовних одиниць) з частотою 10 Гц (інтервал таймера 0.1 с), що імітує роботу реального дискретного датчика.

    Транспортний шар (Topic): Дані публікуються у глобальний топік /sensor_data за допомогою стандартизованого типу повідомлення std_msgs/msg/Float32.

    Фільтрація та обробка: Перед публікацією сирі дані проходять через буфер рухомого середнього (Moving Average Filter), що дозволяє згладити випадкові шуми та викиди.

    Рівень безпеки (Threshold Monitoring): Нода порівнює фільтроване значення з критичним порогом (0.5). У разі фіксації небезпечного наближення генерується попередження (WARN-повідомлення) у системному лозі ROS2.

2. Фрагменти коду фільтрації

Для реалізації рухомого середнього (усереднення) та перевірки порогового значення у файлі sensor_node.py було використано такий фрагмент коду:
Python

        # Ініціалізація параметрів фільтрації та порогу
        self.window_size = 5          # Розмір вікна для усереднення
        self.readings_buffer = []     # Буфер історії вимірювань
        self.threshold = 0.5          # Критичний поріг спрацювання

    def timer_callback(self):
        # 1. Генерація сирих тестових даних
        raw_value = round(random.uniform(0.1, 2.0), 2)
        
        # 2. Реалізація усереднення значень (рухоме середнє)
        self.readings_buffer.append(raw_value)
        if len(self.readings_buffer) > self.window_size:
            self.readings_buffer.pop(0) # Видаляємо найстаріше значення
        
        filtered_value = sum(self.readings_buffer) / len(self.readings_buffer)
        filtered_value = round(filtered_value, 2)
        
        # 3. Перевірка порогового значення та генерація WARN
        if filtered_value < self.threshold:
            self.get_logger().warning(
                f'УВАГА! Критичне значення! Сире: {raw_value}, Фільтроване: {filtered_value} (Поріг: {self.threshold})'
            )
        else:
            self.get_logger().info(f'Сире: {raw_value} | Фільтроване: {filtered_value}')

        # Публікація оброблених даних у топік
        msg = Float32()
        msg.data = float(filtered_value)
        self.publisher_.publish(msg)

Для звіту тут радять зробити та додати два скриншоти:

    Скриншот роботи сенсорної ноди в терміналі:
    Показує процес виконання ноди командою ros2 run sensor_node sensor_node, де видно виведення INFO-повідомлень із поточними та фільтрованими значеннями.

    Скриншот перевірки топіка:
    Показує результат виконання команди ros2 topic echo /sensor_data, де відображається потік числових даних типу std_msgs/msg/Float32, які надсилаються у систему в реальному часі.

4. Демонстрація реакції системи

Під час тестування ноди було перевірено реакцію системи на критичні значення вимірювань:

    Коли згенеровані випадкові значення призводили до того, що усереднений показник ставав меншим за встановлений поріг (< 0.5), нода миттєво реагувала генерацією попередження рівня WARN.

    У терміналі це виглядало наступним чином:
    Plaintext

    [WARN] [timestamp] [sensor_node]: УВАГА! Критичне значення! Сире: 0.15, Фільтроване: 0.38 (Поріг: 0.5)

    Завдяки використанню фільтрації на основі буфера, поодинокі випадкові «стрибки» датчика не викликали хибних спрацьовувань порогового контролю, що підтвердило надійність та стійкість розробленого алгоритму обробки даних.

5. Висновки

Під час виконання Лабораторної роботи №4 було:

    Створено спеціалізований Python-пакет (sensor_node) для інтеграції віртуального сенсора в екосистему ROS2.

    Налаштовано стабільну періодичну публікацію даних у топік /sensor_data із частотою 10 Гц із використанням стандартних типів повідомлень (std_msgs/msg/Float32).

    Реалізовано алгоритм базової цифрової фільтрації (рухоме середнє), який ефективно нівелює випадкові похибки вимірювань і шуми сенсора.

    Додано систему порогового контролю з генерацією попереджувальних (WARN) повідомлень, що дозволяє вчасно виявляти небезпечні стани (наприклад, наближення до перешкод) та може слугувати основою для побудови систем активної безпеки та запобігання зіткненням мобільного робота.
